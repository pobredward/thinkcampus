## 1. 벤치마크 요약

### 1.1 국내 학원 ERP (학원온, 클래스업, 에드펜, 킵스쿨 등)

공통으로 **원장/관리자 화면**에 다음 축이 있다.

| 축 | 대표 기능 |
|----|-----------|
| **대시보드** | 오늘 수업·미처리 출결·미납·상담 대기를 한 화면에 |
| **원생(학생)** | 프로필, 반 배정, 상담 이력, 형제/가족 |
| **출결** | 일/월 캘린더, 다중 입력 방식, 결석 자동 알림 |
| **수업·일정** | 반·시간표·강사 배정 |
| **강사** | 스케줄, 급여(선택), 담당 반 |
| **학부모** | 앱/알림톡, 공지, 상담, 수납 |
| **수납·정산** | 청구·미납·환불 (사설 학원 핵심) |
| **메시지** | 공지·예약 발송·템플릿 |

클래스업 등은 **「여러 화면을 돌며 현황을 모으는 시간」을 줄이는 홈/AI 요약**을 강조한다.

### 1.2 방과후·학교 연계 (Homeroom, Jumbula, Clasero, Afterschool Tracker)

| 축 | 대표 기능 |
|----|-----------|
| **프로그램/시즌** | 등록 기간·학기 단위 운영 |
| **실시간 출석 보드** | 캠퍼스 전체 프로그램 오늘 현황 |
| **강사 로스터** | 회차별 링크·출석·메모 (로그인 없이도 링크 출석) |
| **학부모 포털** | 일정·출석·청구(선택) 조회 |
| **픽업/키오스크** | 유아·방과후 특화 (ThinkCampus 1차 범위 밖) |
| **리포트·감사** | CSV·변경 이력 |

### 1.3 ThinkCampus 포지션

- **사설 학원 수납 ERP가 아님** — 지자체 `contractCode` 운영 건, 캠퍼스 실행, **학부모 앱(출결·리포트)** 이 핵심.
- 센터 관리자 = **「캠퍼스 원장」**: 회사가 내려준 운영 건을 **실행**하고, **학생·학부모·강사**를 묶어 **출결·리포트·소통**까지 책임.
- 회사 관리자 = **「본사 운영」**: 명단 import, 운영 건 생성·배포, 템플릿, 전사 정책.

## 2. 센터 원장 업무 맵 (ThinkCampus 데이터와 연결)

| 업무 영역 | 원장이 하는 일 | 주요 데이터 |
|-----------|----------------|-------------|
| **오늘 운영** | 오늘 회차 확인, 강사 부재·교실·휴강 대응 | `runSessions`, `programRuns` |
| **출결** | 미입력 회차 처리, 강사 입력 검수·정정, 학부모 알림 트리거 | `sessionAttendance`, `notifications` |
| **수강생** | 명단 확인, 반(운영 건)별 수강, 형제 가구, 등록코드 미사용자 | `students`, `studentProgramEnrollments`, `enrollmentCodes`, `householdId` |
| **학부모** | 앱 연결 여부, 초대·재발송, 민원·연락처 확인 | `guardianLinks`, Auth, `addGuardianPhone` |
| **강사** | 회차 배정, 대체, 연락, 출결·리포트 작성 여부 | `staff`, `runSessions.instructorId`, (향후) 강사 앱 |
| **리포트** | 강사 초안 → **센터 검수** → 학부모 공개 | `sessionReports`, `reportPolicy` |
| **소통** | 캠퍼스·운영 건 공지, 휴강·보강 안내 | `notifications`, (향후) `programRuns` 공지 필드 |
| **Compliance** | 출석·리포트 기록 보관, 감사용 export | Functions + CSV |

**1차에서 제외·후순위**: 수강료 청구·미납(지자체 계약 구조상 별도), 좌석/키오스크, CRM 상담 파이프라인(에드펜형).

## 3. 정보 구조(IA) — 센터 관리자 앱

### 3.1 전역 컨텍스트 (헤더)

- **캠퍼스명** (예: 달성캠퍼스) + 역할 「센터 관리」
- **운영 건 `contractCode`**: 회사가 해당 캠퍼스에 **부여한 건만** 목록. 2개 이상이면 **우측 상단 셀렉트(토글)** — 모든 하위 화면 필터 기준.
- 계정: `staff` + `centerAdmin` claim, `campusIds`

「ThinkCampus Admin」 브랜드는 **로그인·회사 화면**에 두고, 센터 앱 타이틀은 **캠퍼스 운영**으로 분리 (현재 `StaffAppShell` 방향 유지·강화).

### 3.2 하단 탭 (4탭 핵심 체제)

모바일 원장 사용성(터치 영역 ~95px, 시인성)을 극대화하기 위해 **4개 핵심 탭**으로 슬림화하고, 빈도가 불규칙한 **리포트 검수·공지 발송은 홈 대시보드의 액션 센터(Action Center)** 로 직결한다.

| 탭 | 라벨 | 경로 | 핵심 역할 |
|----|------|------|-----------|
| 1 | **홈** | `/` | 오늘의 관제탑 · 긴급 처리 카드(출결·리포트·미연결·미배정) · 빠른 실행(공지/리포트) |
| 2 | **수업** | `/lessons` | 인라인 반 필터 · 시간대별 로테이션 보드 · 반별 출결 시트 직결 |
| 3 | **학생** | `/students` | 인라인 반 필터 · 이름 검색 · 보호자 연결 필터 · 원터치 연락/초대 복사 |
| 4 | **강사** | `/instructors` | 등록 강사 명단 · 주간 배정 현황 · 미배정 회차 경고 및 `/instructors/[staffId]` 배정 |

*레거시 경로(`/people`, `/people/students`, `/roster` 등)는 `/students` 또는 `/instructors`로 자동 리다이렉트.*

## 3.3 각 탭별 세부 기능 고도화 기획

### ① [홈 탭] — "오늘의 관제탑 & Action Center"
- **오늘의 로테이션 브리핑 카드**: 오늘 타임 수, 총 회차 수, 활성 반 수, 터치 시 즉시 당일 로테이션 보드로 이동.
- **긴급 조치(Actionable Items) 4대 카드**:
  1. **출결 미완료**: 오늘자 미입력 회차 건수 → 수업 탭 미완료 필터로 직결.
  2. **리포트 검수 대기**: 강사가 제출한 검수 대기 리포트 건수 → `/reports` 검수 뷰로 직결.
  3. **학부모 미연결**: 등록코드 미연결 학생 수 → `/students?guardian=unlinked`로 직결.
  4. **강사 미배정**: 아직 강사가 지정되지 않은 수업 회차 수 → `/instructors` 배정 화면으로 직결.
- **빠른 실행(Quick Shortcuts)**:
  - 💬 **공지 및 소통 (`/comms`)**: 알림톡 발송, 공지 작성, 이력 확인
  - 📄 **회차 리포트 (`/reports`)**: 회차별 리포트 검수 및 학부모 공개

### ② [수업 탭] — "로테이션 보드 & 실시간 출결"
- **헤더 슬림화 & 인라인 반 필터**: 헤더 아래의 무거운 전역 필터를 걷어내고, 수업 화면 상단에 `CenterSectionChips` 배치(전체 및 1~8반 가로 스크롤).
- **날짜 퀵 네비게이터**: 당일 날짜가 아닐 때 즉시 오늘로 돌아오는 [오늘] 원터치 버튼 제공.
- **로테이션 타임라인 카드 고도화**:
  - 타임별(1교시, 2교시...) 병렬 진행 반 카드 나열.
  - 담당 강사 배정 상태 및 출결 입력 상태(완료/미완료) 칩.
  - 카드 터치 시 바로 해당 반의 출결 입력 시트(`/attendance`)로 진입.

### ③ [학생 탭] — "원생 관리 & 학부모 원터치 소통"
- **검색 및 보호자 연결 상태 필터**:
  - 이름 검색창 (로컬 debounce로 타이핑 끊김 방지)
  - `전체` / `보호자 미연결` / `보호자 연결됨` 3개 필터 칩
  - 미연결 학생 수 실시간 카운트 배지
- **학생 카드 인터랙션 강화**:
  - 학생 프로필 사진, 반 배정 라벨, 가족(형제) ID
  - 보호자 연결 상태 인디케이터
  - **원터치 액션 버튼**:
    - 보호자 연결됨: `[보호자 연락]` 버튼 (연락 다이얼로그)
    - 보호자 미연결: `[초대 복사]` 버튼 (클립보드에 학부모 앱 연결 등록코드 및 가이드 자동 복사)

### ④ [강사 탭] — "강사 명단 & 회차 배정 매칭"
- **배정 현황 게이지 및 경고**:
  - 이번 주 강사 미배정 회차가 발생했을 때 상단에 경고 배너 표시 및 원터치 배정 지원.
- **강사 프로필 카드**:
  - 강사 프로필 사진, 이메일/연락처, 전문 분야 태그.
  - 이번 주 담당 회차 수 표시 (예: 4회차 담당).
  - 강사 카드 터치 시 상세 프로필 및 회차 배정 화면(`/instructors/[staffId]`) 진입.

## 4. 회사 관리자 IA (정렬)

센터와 **동일한 앱 패턴**(헤더 + 하단 탭), 브랜드는 「회사 관리」.

| 탭 | 라벨 | 목적 |
|----|------|------|
| 홈 | **홈** | 전사 운영 건 수, 최근 import, 캠퍼스별 이슈 요약 |
| 명단 | **명단** | roster import (dryRun → 반영) |
| 운영 건 | **운영 건** | 생성·목록·`contractCode` · **캠퍼스 배정** |
| 리포트 | **정책** | `reportPolicy`, 템플릿 (후순위) |
| 더보기 | **설정** | 스태프 권한, 캠퍼스 카탈로그 (후순위) |

회사가 운영 건에 `campusId`(들)를 지정하면, 센터 앱에는 **그 건만** 노출.

## 5. 강사·학부모·센터 역할 분리 (출결·리포트)

| 역할 | 출결 | 회차 리포트 |
|------|------|-------------|
| **강사** | 1차 입력 (선택·추후 자동출결) | 초안 작성 |
| **센터** | 검수·정정·공식 기록 | 검수·발행 |
| **학부모** | 조회 | 조회 (published 후) |

센터 앱 「수업」에서 **강사 입력 vs 센터 확정** 상태를 구분 표시 (예: `recordedByUid`, `updatedAt`).

## 6. 구현 단계 (로드맵)

### Phase A — IA 개편 (체험판 + 골격)

- [ ] 하단 탭: 홈 / 수업 / 사람 / 리포트 / 소통 (센터)  
- [ ] 홈 대시보드 카드 (더미 KPI)  
- [ ] 사람: 수강생·학부모·강사 더미 3뷰  
- [ ] 수업: 회차 리스트 + 기존 출결 시트 연결  
- [ ] 운영 건 헤더 셀렉트 유지

### Phase B — Firestore 연동

- [ ] 홈 KPI 쿼리 (오늘 `runSessions`, 미출결 `sessionAttendance`)  
- [ ] 사람 탭: `students` + `guardianLinks` + `staff`  
- [ ] 리포트 탭: `sessionReports` 상태 필터  
- [ ] 소통: `notifications` 읽기 + 공지 작성 API

### Phase C — 워크플로 완성

- [ ] 리포트 검수·발행  
- [ ] 강사 앱 ↔ 센터 검수 알림  
- [ ] export CSV (출결·수강생)

### Phase D (선택)

- [ ] 상담 메모, 자동 알림톡 템플릿, 지자체 보고서 양식

## 7. 현재 체험판 vs 목표 Gap

| 현재 `/demo/center` | 목표 |
|---------------------|------|
| 홈 + 출결 + 수강생 + 내 정보 | 홈 + **수업** + **사람**(3분류) + **리포트** + **소통** |
| 출결만 강조 | 원장 **전체 업무** 허브 |
| 학부모·강사 화면 없음 | 사람 탭에 통합 |

## 8. UX 원칙

1. **운영 건이 항상 헤더 컨텍스트** — 탭을 바꿔도 필터 유지.  
2. **홈은 “할 일”만** — 통계 대시보드는 2차.  
3. **학부모·강사는 “사람” 한곳** — 원장은 연락·연결 상태를 같이 봄.  
4. **회사 Admin과 UI 패턴 통일** — 학습 비용↓, 역할만 다름.  
5. **수납 없음을 명시** — 지자체 프로그램에 맞는 범위 관리.
