## 1. 벤치마크 요약

### 1.1 국내 학원 ERP (학원온, 클래스업, 에드펜, 킵스쿨 등)

공통으로 **원장/관리자 화면**에 다음 축이 있다.

| 축 | 대표 기능 |
|----|-----------|
| **대시보드** | 오늘 수업·미처리 출결·미납·상담 대기를 한 화면에 |
| **원생(학생)** | 프로필, 반 배정, 상담 이력, 형제/가족 |
| **출결** | 일/월 캘린더, 다중 입력 방식, 결석 자동 알림 |
| **수업·일정** | 반·시간표·강사 배정 |
| **강사** | 스케줄, 급여(선택), 담당 반 |
| **학부모** | 앱/알림톡, 공지, 상담, 수납 |
| **수납·정산** | 청구·미납·환불 (사설 학원 핵심) |
| **메시지** | 공지·예약 발송·템플릿 |

클래스업 등은 **「여러 화면을 돌며 현황을 모으는 시간」을 줄이는 홈/AI 요약**을 강조한다.

### 1.2 방과후·학교 연계 (Homeroom, Jumbula, Clasero, Afterschool Tracker)

| 축 | 대표 기능 |
|----|-----------|
| **프로그램/시즌** | 등록 기간·학기 단위 운영 |
| **실시간 출석 보드** | 캠퍼스 전체 프로그램 오늘 현황 |
| **강사 로스터** | 회차별 링크·출석·메모 (로그인 없이도 링크 출석) |
| **학부모 포털** | 일정·출석·청구(선택) 조회 |
| **픽업/키오스크** | 유아·방과후 특화 (ThinkCampus 1차 범위 밖) |
| **리포트·감사** | CSV·변경 이력 |

### 1.3 ThinkCampus 포지션

- **사설 학원 수납 ERP가 아님** — 지자체 `contractCode` 운영 건, 캠퍼스 실행, **학부모 앱(출결·리포트)** 이 핵심.
- 센터 관리자 = **「캠퍼스 원장」**: 회사가 내려준 운영 건을 **실행**하고, **학생·학부모·강사**를 묶어 **출결·리포트·소통**까지 책임.
- 회사 관리자 = **「본사 운영」**: 명단 import, 운영 건 생성·배포, 템플릿, 전사 정책.

## 2. 센터 원장 업무 맵 (ThinkCampus 데이터와 연결)

| 업무 영역 | 원장이 하는 일 | 주요 데이터 |
|-----------|----------------|-------------|
| **오늘 운영** | 오늘 회차 확인, 강사 부재·교실·휴강 대응 | `runSessions`, `programRuns` |
| **출결** | 미입력 회차 처리, 강사 입력 검수·정정, 학부모 알림 트리거 | `sessionAttendance`, `notifications` |
| **수강생** | 명단 확인, 반(운영 건)별 수강, 형제 가구, 등록코드 미사용자 | `students`, `studentProgramEnrollments`, `enrollmentCodes`, `householdId` |
| **학부모** | 앱 연결 여부, 초대·재발송, 민원·연락처 확인 | `guardianLinks`, Auth, `addGuardianPhone` |
| **강사** | 회차 배정, 대체, 연락, 출결·리포트 작성 여부 | `staff`, `runSessions.instructorId`, (향후) 강사 앱 |
| **리포트** | 강사 초안 → **센터 검수** → 학부모 공개 | `sessionReports`, `reportPolicy` |
| **소통** | 캠퍼스·운영 건 공지, 휴강·보강 안내 | `notifications`, (향후) `programRuns` 공지 필드 |
| **Compliance** | 출석·리포트 기록 보관, 감사용 export | Functions + CSV |

**1차에서 제외·후순위**: 수강료 청구·미납(지자체 계약 구조상 별도), 좌석/키오스크, CRM 상담 파이프라인(에드펜형).

## 3. 정보 구조(IA) — 센터 관리자 앱

### 3.1 전역 컨텍스트 (헤더)

- **캠퍼스명** (예: 달성캠퍼스) + 역할 「센터 관리」
- **운영 건 `contractCode`**: 회사가 해당 캠퍼스에 **부여한 건만** 목록. 2개 이상이면 **우측 상단 셀렉트(토글)** — 모든 하위 화면 필터 기준.
- 계정: `staff` + `centerAdmin` claim, `campusIds`

「ThinkCampus Admin」 브랜드는 **로그인·회사 화면**에 두고, 센터 앱 타이틀은 **캠퍼스 운영**으로 분리 (현재 `StaffAppShell` 방향 유지·강화).

### 3.2 하단 탭 (5탭 권장)

모바일 원장 사용 패턴·벤치마크(일정/출결/원생/강사/공지)를 합쳐 **ThinkCampus 전용**으로 재구성.

| 탭 | 라벨 | 목적 | 핵심 화면 |
|----|------|------|-----------|
| 1 | **홈** | 오늘 할 일·리스크 | 대시보드 카드 |
| 2 | **수업** | 일정·회차·출결 진입 | 캘린더/리스트 → 회차 시트 |
| 3 | **사람** | 학생·학부모·강사 | 3서브탭 또는 필터 칩 |
| 4 | **리포트** | 검수·발행 대기 | `centerReviewed` 워크플로 |
| 5 | **소통** | 공지·알림 이력 | 발송·예약(후순위) |

**「내 정보」**: 탭이 아니라 홈 우측 상단 ⚙ 또는 홈 하단 링크 (학부모 앱의 「내 정보」=탭과 동일 패턴).

#### 홈 카드 (벤치마크: 클래스업 「오늘 먼저 할 일」)

1. **오늘 회차 N건** — 탭하면 수업 탭 오늘 필터  
2. **출결 미입력** — 회차별 건수  
3. **리포트 검수 대기** — 강사 제출·draft 건수  
4. **학부모 미연결** — `enrollmentCodes` used but no `guardianLinks` / 미등록 코드  
5. **강사 미배정 회차** — `instructorId` 비어 있는 `runSessions` (선택)

### 3.3 「사람」 탭 상세

| 서브 | 기능 |
|------|------|
| **수강생** | 운영 건 필터, 검색, 가구(형제), 수강 상태, 등록코드 상태 |
| **학부모** | 자녀별 연결 보호자 목록, 연결일, 관계, **연결 안 됨** 강조, 초대 재안내(정책에 따라 센터는 “안내 문구 복사”만) |
| **강사** | 캠퍼스 소속 `staff`(instructor), 담당 회차 수, 이번 주 일정, 연락(이메일/전화) |

### 3.4 「수업」 탭 상세

- **주간/일간** 뷰: `runSessions.scheduledDate`  
- 회차 카드: 주제, 시간, 장소, 담당 강사, 출결 입력률  
- 진입 → **출결 시트** (현재 `/center/attendance` 기능 흡수)  
- 휴강·보강: `programRuns` excludedDates / 보강 회차 (DATA_MODEL 운영 건)

### 3.5 「리포트」 탭

- 상태: `draft` (강사) → **센터 검수** → `published`  
- 학생·회차별 미리보기, 일괄 승인/반려 코멘트 (후순위)  
- 학부모 앱 노출 시점과 연동

### 3.6 「소통」 탭

- 발송 이력 (`notifications`)  
- 운영 건·캠퍼스 **공지** 작성 (학부모 앱 알림/공지 영역과 동일 소스)  
- 출결·리포트 발행 시 자동 알림은 Functions — 센터는 **템플릿·수동 공지**만 1차

## 4. 회사 관리자 IA (정렬)

센터와 **동일한 앱 패턴**(헤더 + 하단 탭), 브랜드는 「회사 관리」.

| 탭 | 라벨 | 목적 |
|----|------|------|
| 홈 | **홈** | 전사 운영 건 수, 최근 import, 캠퍼스별 이슈 요약 |
| 명단 | **명단** | roster import (dryRun → 반영) |
| 운영 건 | **운영 건** | 생성·목록·`contractCode` · **캠퍼스 배정** |
| 리포트 | **정책** | `reportPolicy`, 템플릿 (후순위) |
| 더보기 | **설정** | 스태프 권한, 캠퍼스 카탈로그 (후순위) |

회사가 운영 건에 `campusId`(들)를 지정하면, 센터 앱에는 **그 건만** 노출.

## 5. 강사·학부모·센터 역할 분리 (출결·리포트)

| 역할 | 출결 | 회차 리포트 |
|------|------|-------------|
| **강사** | 1차 입력 (선택·추후 자동출결) | 초안 작성 |
| **센터** | 검수·정정·공식 기록 | 검수·발행 |
| **학부모** | 조회 | 조회 (published 후) |

센터 앱 「수업」에서 **강사 입력 vs 센터 확정** 상태를 구분 표시 (예: `recordedByUid`, `updatedAt`).

## 7. 현재 체험판 vs 목표 Gap

| 현재 `/demo/center` | 목표 |
|---------------------|------|
| 홈 + 출결 + 수강생 + 내 정보 | 홈 + **수업** + **사람**(3분류) + **리포트** + **소통** |
| 출결만 강조 | 원장 **전체 업무** 허브 |
| 학부모·강사 화면 없음 | 사람 탭에 통합 |

## 8. UX 원칙

1. **운영 건이 항상 헤더 컨텍스트** — 탭을 바꿔도 필터 유지.  
2. **홈은 “할 일”만** — 통계 대시보드는 2차.  
3. **학부모·강사는 “사람” 한곳** — 원장은 연락·연결 상태를 같이 봄.  
4. **회사 Admin과 UI 패턴 통일** — 학습 비용↓, 역할만 다름.  
5. **수납 없음을 명시** — 지자체 프로그램에 맞는 범위 관리.
