## 1. 회의록 요지

### 1-1. 체험판 시연 화면 훑기
- 대표 시연용으로 메인에서 바로 들어가는 체험판(골드 디자인)을 만들었고, 모바일에서 보면 괜찮다. **채팅을 붙이는 것도 일이 아니라서 해 보겠다**(신선웅).
- 프로그램 목적 페이지: **"대학생 멘토 수업" 표현은 빼자**(대표). 지금은 더미 문구라 무엇이 들어가는지만 보여 주는 단계.
- 공지사항이 눌러야 보이는 위치에 있다 → 나중에 **진짜 공지사항**을 넣고 잘 보이게.
- 회차별 수업은 간단히 → 누르면 일정·내용. 강사 소개도 미리 넣어야.

### 1-2. 핵심 — "담당 공무원이 걱정하는 건 민원"
- 센터 관리자 화면을 보던 대표: **관리자(공무원)가 보고 싶은 것은 민원 발생·처리 현황.** 단순 문의와 민원을 구분해 **접수 n건 · 처리 n건**, 민원은 한 건씩 상세(예: "너무 덥다", "강사 태도가 불량하다")를 **여과 없이** 보고, 우리가 **어떻게 처리했는지**까지 보이게.
- 그 외 담당 공무원이 한 화면에서 보고 싶은 것: **학생 참여도(출결 — 30명 중 1주차 29명, 2주차 …)**, **강사진 구성·프로필**, **회차별 프로그램 내용**(1회차는 무엇, 2회차는 무엇, 다음 3회차 예정), 학부모에게 무엇을 보냈고 어떻게 마무리했는지. 담당자는 이것으로 **사업 보고서를 써야 하므로** 이 화면 하나면 되게.
- 신선웅: 그러면 **지자체 담당자가 보는 페이지를 하나 따로** 만들어, 민원·다음 수업 등을 그 입장에서 보게 하고, **보고서 PDF·HWP 바로 다운로드**까지.
- 대표: 담당자에게는 **링크 + 아이디·비밀번호**를 주면 로그인해서 본다.

### 1-3. 3개 섹터 구조
- **내부용**(우리 라인): 강사 / 프로그램만 진행하는 **프로그램 매니저** / 발주처·전체를 아우르는 **통합 관리 매니저** — 지금의 강사·센터·회사 3개가 그대로 대응.
- **외부용**(제3자): **학부모** / **발주처 담당 공무원**.
- 시연 때 3개 섹터(내부 · 발주처 · 학부모)로 구분해 보여 주면 한눈에 들어온다.

### 1-4. 학부모 만족도·후기
- 프로그램이 끝나고 데이터를 학부모에게 보내고 나면 **학부모 후기(소감) 칸**. 공무원은 학부모 만족도를 반드시 받으므로, 우리가 앱에서 받아 두면 **담당자가 학부모에게 따로 받을 필요가 없다.**
- 후기까지 모아 **전체를 리포트로 추출**.

### 1-5. 보고서 생성 — "양식 만들기"
- 담당 공무원이 쓰는 **양식(샘플) 하나를 넣어 두고**, 종합해서 **[양식 만들기] → 다운로드**. **PDF, 수정 가능한 워드·엑셀, HWP.** 담당자는 제목·단어만 살짝 고쳐 자기 보고서 목차에 놓기만 하면 된다.
- 프로그램 개요(목적·시수 등)도 **[개요 정리하기]** 버튼으로 양식에 맞춰 뽑기. 신선웅: HWP 수정 가능 파일로, 들어갈 항목(목적·시수 등)을 골라 순서대로 추출 → 가능.
- 대표: 그렇게 **리뉴얼**하자.

## 4. 기획안

### 4-1. 체험판 허브 3섹터 재구성 (E6 · E7)

허브 `/demo` 를 세 묶음으로:

```
[내부 운영]   통합 관리자(본사) · 프로그램 매니저(캠퍼스) · 강사
[발주처]      담당 공무원 — 달성군 교육지원과 ○○○ 주무관
[학부모]      손영란 학부모 — 자녀 신민준 · 신서연
```

- 역할 이름 정리: 화면 제목·배너·허브에서 "센터 관리자" → **프로그램 매니저**, "회사 관리자" → **통합 관리자**. 주소(`/admin/center`, `/admin`)·권한 이름(`centerAdmin`·`companyAdmin`)은 그대로.
- 허브에 시연 순서 안내 한 줄("내부 → 발주처 → 학부모 순으로 보시면 흐름이 이어져요").
- 목적 문구·특징에서 "대학생 멘토" 제거(`data/dummyProgram.ts` — 웹·모바일 동일). 공지사항: 체험 세계의 공지(`notifications`)를 홈 카드 위에 "최신 공지 1줄 · 전체 보기"로.

### 4-2. 발주처 담당자 포털 (E1 · E2) — `/partner`

**대상** 지자체 담당 공무원(사업 발주·감독). PC 로 보고 파일을 내려받는 경우가 많으므로 **데스크톱 우선 레이아웃**(표·2열), 휴대폰에서도 깨지지 않게.

**로그인** `/partner/login` — 아이디(이메일)·비밀번호(Firebase Email/Password). 계정은 통합 관리자가 운영 건에서 **[담당자 초대]**로 만든다(이메일 + 임시 비밀번호 발급 → 첫 로그인 때 변경). 한 담당자는 여러 운영 건을 볼 수 있다(`programRunIds`).

**화면 (상단 탭 5개)**

| 탭 | 내용 |
|---|---|
| **현황** (홈) | 운영 건 선택(여러 개면) → 4칸 요약: **진행 4/6회차** · **평균 출석률 96%** · **민원 접수 3 / 처리 3** · **문의 12 / 답변 12** → 주차별 출석 표(1주차 29/30 · 2주차 30/30 …, 막대) → 다음 수업(날짜·주제·강사) → 최근 민원 3건 → 최근 공지·안내 발송 |
| **수업** | 회차별 카드: 날짜·주제·강사·완료/예정, 눌러 활동 내용(목표·흐름·준비물)·출석 결과·사진(선택). "예정" 회차도 내용이 보여 다음 수업이 무엇인지 알 수 있게 |
| **민원·문의** | 목록(민원/문의 필터 · 상태 필터 · 카테고리) → 상세: 접수 일시·경로(앱/전화/현장)·내용 원문·**처리 내용·처리 일시·처리 담당** · 학부모 만족(처리 후 평가, 선택). 담당자는 **읽기 전용**, 필요하면 "지자체 의견" 한 줄 남기기 |
| **참여** | 출결: 학생별 × 회차 표(출석/지각/결석), 반별·주차별 집계, XLSX 내려받기. 명단은 이미 담당자가 가진 신청자 명단이므로 이름 표시(설정으로 마스킹 가능). 만족도: 설문 평균·분포·후기 목록(공개 동의한 것) |
| **강사진** | 회차 담당 강사 프로필 카드(이름·소속·전문·소개·담당 회차), 프로그램 매니저·캠퍼스 연락처 |
| **보고서** | §4-5 |

**데이터 조회** Callable `partner*` 5개(현황·수업·민원·참여·강사). 모두 `programRunId` 로 범위를 제한하고 역할 `officer` + `programRunIds` 확인.

### 4-3. 채팅 탭 — 담당 선생님과 바로 대화, 민원은 그 안에서 접수 (E3)

**목적** 수업 준비(준비물·장소·시간)나 수업 과정에서 궁금한 것이 생기면 학부모가 **앱 하단 [채팅] 탭에서 담당 선생님(프로그램 매니저)과 바로** 대화한다. 전화·문자로 흩어지던 문의가 한곳에 남고, 불편·요청은 그 대화에서 바로 **민원으로 접수**돼 담당 공무원에게까지 이어진다.

**학부모 앱**
- 하단 탭을 **홈 · 채팅 · 알림 · 내 정보** 4개로. 채팅 탭에 안 읽은 메시지 배지.
- 채팅 목록: 자녀·프로그램마다 대화방 하나 — "달성캠퍼스 담당 선생님 · 신민준 · 토요 창의융합". 지난 프로그램 방은 종료 후 30일까지 읽기 전용으로 남김.
- 대화방: 카카오톡처럼 말풍선(내 것은 골드 톤, 담당자는 카드 톤), 시간·읽음, 사진 첨부, 입력창 위에 **빠른 질문 칩** — "다음 수업 준비물" · "결석·지각 알려요" · "장소·주차" · "기타". 칩을 누르면 문장이 채워지고, "결석·지각"은 날짜 선택 → 센터 출결에 "사전 연락" 표시(다음 단계).
- **불편·요청 사항으로 접수** 토글(보내기 전) — 켜고 보내면 그 메시지가 민원으로 접수되고 "접수됐어요 · 처리되면 알려 드려요" 시스템 메시지. 학부모는 상태(접수 → 처리 중 → 완료)를 대화방 상단 배지로 본다.
- 시스템 메시지: 회차 D-3 준비물·장소 안내, 출결 등록, 리포트 공개, 민원 처리 결과 — 같은 방에 흘러 들어와 "여기만 보면 된다"가 되게. (알림 탭과 중복되지만 채팅은 대화, 알림은 기록)
- 첫 진입 안내: "수업 준비·진행 중 궁금한 점을 담당 선생님께 바로 물어보세요. 평일 09–18시 안에 답해 드려요."(운영 시간은 캠퍼스 설정)

**센터(프로그램 매니저) 앱**
- 하단 탭 **홈 · 수업 · 채팅 · 리포트 · 더보기**(학생·강사·공지·내 정보는 더보기로). 채팅 탭 배지 = 안 읽은 방 수.
- 목록: 운영 건 필터, 안 읽음·민원 우선 정렬, 학생 이름·반·마지막 메시지. 대화방: 답장, 사진, **"민원으로 등록"**(학부모가 토글을 안 켰어도 센터가 지정) · 민원 카드에서 **처리 내용·상태** 입력(내부용 + 담당자 포털에 보임) · "자주 쓰는 답변"(준비물 안내·주차 안내 등 캠퍼스별 저장).
- 전화·현장 민원: 대화방 없이 **민원 직접 등록**(접수 경로 전화/현장) — 담당자 포털에는 채팅 민원과 같은 목록에 보인다.
- 통합 관리자(회사)는 모든 캠퍼스의 채팅·민원을 읽을 수 있고, 답장은 캠퍼스 담당이 한다(필요하면 회사도).
- 강사는 채팅에 들어오지 않는다(강사 앱은 그대로). 담당 선생님 = 캠퍼스 프로그램 매니저.

**담당자 포털** — 채팅 원문은 보이지 않고, **민원으로 접수된 것만** 원문 + 처리 내용이 보인다(대표 결정 "여과 없이"). 문의는 건수·답변률만.

**실시간** Firestore `onSnapshot` 으로 웹·모바일 모두 즉시 반영. 새 메시지 푸시·문자는 지난 회의 4-3(푸시+문자)과 함께.

**규칙** 답변 목표 시간(운영 시간 안 2시간)을 센터 홈에 "미답변 n건 · 가장 오래된 1시간 20분"으로. 민원은 상태가 완료가 될 때까지 센터 홈에 남는다.

### 4-4. 학부모 만족도 설문 · 후기 (E4)

- **시점** 마지막 회차 완료 또는 종합 리포트 발급 시 홈에 "만족도 설문에 참여해 주세요" 카드 + 알림(푸시/문자 연동은 지난 회의 4-3). 종합 리포트 화면 맨 아래에도 링크.
- **문항(기본 5개 · 5점)** 전반적인 만족 / 수업 내용 / 선생님 / 운영·안내(공지·장소·시간) / 다음에도 참여하고 싶다 + **자유 후기** + **"후기를 지자체·다른 학부모에게 공개해도 좋아요"** 동의(기본 꺼짐). 문항은 운영 건별로 바꿀 수 있게(`surveyTemplate`).
- **결과** 담당자 포털 [참여 › 만족도]: 응답률(30명 중 24), 문항별 평균·분포 막대, 후기 목록(공개 동의분, 이름 마스킹 옵션). 보고서 "학부모 만족도" 섹션에 자동 삽입. 종합 리포트와는 별개(학생 평가 ↔ 학부모 평가).
- 학부모는 한 번 제출 후 수정 가능(마감 전), 마감은 종료 후 2주(설정).

### 4-5. 보고서 생성 (E5)

**목표** 담당 공무원이 사업 보고서를 쓸 때 우리 화면 하나에서 **양식대로 뽑아** 제목·단어만 고치게.

**섹션 블록(체크·순서 조정)**
1. 사업 개요 — 사업명·계약(공고)번호·기간·장소·대상·인원·시수(회차 × 차시)·주최/운영
2. 사업 목적·도입 취지 — 운영 건의 `purpose`/`introduction` 그대로
3. 운영 일정 — 회차별 날짜·시간·주제·강사 표
4. 회차별 운영 내용 — 회차마다 목표·활동·준비물 + 출석 결과(사진은 선택)
5. 강사진 — 프로필 표
6. 참여 현황 — 반별·주차별 출석률 표 + 그래프, 지각·결석 사유 요약
7. 민원·문의 접수 및 처리 — 건수 표 + 민원별 접수·처리 내역
8. 학부모 만족도 — 문항별 평균·분포, 후기 발췌(공개 동의분)
9. 학생 종합 평가 요약 — 종합 리포트 등급 분포·강점 영역 상위(개별 리포트는 별도 발급)
10. 종합 의견·향후 계획 — 운영사 의견(프로그램 매니저가 입력)

**출력** (확정 2026-09-30: HWPX 까지 이번에)
- **HWPX** — 한글 표준 문서(OWPML, XML 묶음). 서버(Cloud Function)에서 직접 생성: 제목·본문 문단, 표(출결·회차·민원·만족도), 그래프는 PNG 로 넣는다. 한글 2020 이상에서 열리고 그대로 수정 가능. 공무원 환경에 맞는 기본 글꼴(함초롬바탕·돋움) 지정. `.hwp`(바이너리) 는 만들지 않는다 — 한글에서 HWPX 를 열어 "다른 이름으로 저장 → HWP" 하면 된다.
- **DOCX** — `docx` 라이브러리로 생성(표·그래프 이미지 포함). 수정 가능.
- **PDF** — 같은 문서 모델을 웹에서 PDF 로(현재 종합 리포트 방식).
- **XLSX** — 원자료: 출결 표(학생 × 회차), 만족도 응답, 민원 목록, 명단.
- 네 형식 모두 **같은 "보고서 문서 모델"**(섹션 → 문단·표·그래프 블록)에서 나온다. 형식별 렌더러만 다르므로 섹션을 고치면 네 파일이 같이 바뀐다.
- **[개요 정리하기]** — 섹션 1·2 만 골라 바로 내려받기(대표 요청).
- **담당자 양식 그대로** — 운영 건에 **양식 업로드**(통합 관리자, DOCX 또는 HWPX) → 양식 안 `{{사업명}}` `{{기간}}` `{{회차별_운영내용}}` `{{출결표}}` `{{만족도}}` 같은 자리표시자를 채워 같은 형식으로 내려받기. 자리표시자 목록을 안내 문서로 제공. 양식이 없으면 기본 양식.

**생성 흐름** [양식 만들기] → 섹션 체크 → 생성 요청(Callable `generatePartnerReport`) → 진행 표시(10초 내) → 파일 목록(생성 일시·형식·크기·내려받기) — 파일은 Storage 에 두고 만료 링크로.

### 4-6. 소소한 수정 (E7)
- `data/dummyProgram.ts` 의 목적·특징 문구에서 "대학생 멘토" 제거 → "학교에서 하기 어려운 체험·토론·발표 수업을 전문 강사와 함께하며 …", "한 반 20명 이하 소규모 수업".
- 학부모 홈: 현재 수강 중 카드 위에 **최신 공지 1줄**(제목 · 날짜) → 누르면 알림 탭 공지 필터. 공지가 없으면 안 보임.
- 내 정보의 [문의하기]는 채팅 탭으로 보내는 링크로 바꾼다(§4-3).

## 6. 권한 · 보안

- 역할 `officer` 는 **자기 `programRunIds` 의 데이터만** 읽는다(Callable 안에서 검사, Firestore 직접 읽기 없음). 쓰기는 `officerNote` 와 보고서 생성 요청뿐.
- 담당자에게 보이지 않는 것: 학부모 연락처·생년월일·등록코드, 강사 연락처(캠퍼스 대표 번호만), 리포트 초안. 학생 이름은 보임(설정 `partnerNameMasking` 으로 "김○준").
- 후기 공개는 학부모 동의분만. 민원 원문은 노출하되 작성자 이름은 학생 이름·반으로만.
- 계정 발급·정지는 통합 관리자만(`inviteOfficer` · `revokeOfficer`). 임시 비밀번호는 화면에 한 번만 표시, 첫 로그인 때 변경 강제.
- 보고서 파일은 Storage 비공개 + 서명 URL(1시간). `partnerReports` 에 생성 기록.

## 8. 체험판 시연 시나리오 (리뉴얼 후)

1. **내부** — 강사 박지훈: 오늘 4반 출결 입력 → 리포트 작성·제출. 프로그램 매니저 이정민: 검수·공개, **민원 1건 처리**("교실이 덥다" → 냉방 점검 완료 입력), 공지 발송. 통합 관리자 신선웅: 운영 건 현황, 담당자 초대 화면.
2. **발주처** — 달성군 교육지원과 담당자 로그인(체험은 클릭 한 번): 현황 4칸(진행 4/6 · 출석률 · 민원 3/3 · 문의 12/12) → 주차별 출석 표 → 민원 상세(원문 + 처리 내용) → 수업 탭에서 다음 5회차 내용·강사 → **[보고서] 양식 만들기 → DOCX 내려받기**(체험판은 브라우저에서 생성).
3. **학부모** — 홈 최신 공지 → **[채팅] 탭**: 담당 선생님과 대화("다음 주 준비물이 뭔가요?" → 답변), "교실이 너무 더워요"를 **불편·요청으로 접수** → 센터 화면에서 처리 → 학부모 방에 처리 결과 시스템 메시지 → 담당자 포털 민원 목록에 반영 → 지난 봄학기: 종합 리포트 · **만족도 설문 제출** → 담당자 화면에 반영되는 것을 다시 보여 주기.

체험 세계 시드: 대화방 2개(신민준·신서연) 각 6~8개 메시지, 민원 3건(냉방·강사 지각·주차 안내) + 문의 12건, 만족도 응답 24/30, 담당자 계정 1개.

| 6 | 지난 회의 4-1 홈 규정 진입·수강 예정 버튼·기간 한 줄 | 1일 | 작음 |
| 7 | 지난 회의 4-2 공통 평가 항목 → 종합 리포트 자동 집계(작성·발급 화면) | 1주 | 지자체 제안서 핵심 |
| 8 | 지난 회의 4-4 규정·Q&A 데이터화 · 4-3 푸시+문자 · 모바일 동기화(문의·설문·공지) | 1.5주 | 실계약 뒤 |

1~4 를 먼저 끝내면 **시연용 리뉴얼**이 완성된다(약 3주). 5 부터 실서비스 연결. 채팅이 급하면 순서를 1 → 3(채팅) → 2 → 4 로.

## 11. 구현 현황 (2026-09-30)

1~5단계(허브 · 채팅 · 만족도 · 담당자 포털 · 보고서 · 담당자 계정 · 실데이터 Callable)를 한 번에 구현했다. 화면은 체험판과 실서비스가 같고, 데이터만 `services/demo` ↔ `services/live`(Functions)로 바뀐다.

|---|---|---|
| 4-1 허브 3섹터 · 역할 이름 · 문구 · 홈 공지 1줄 | `/demo` 세 묶음 · 프로그램 매니저 · 통합 관리자 · 발주처 담당자 · 홈 최신 공지 한 줄 | — |

| 4-3 채팅 | 학부모 `/main/chat` · 센터 `/admin/center/chat` · 민원 장부 `/admin/center/inquiries` · 회사 `/admin/inquiries` | 사진은 Storage 대신 `chatPhotos` 문서(Storage 버킷 · 규칙을 새로 열지 않음). "결석·지각"은 글 틀만(출결 "사전 연락" 표시는 다음) |
